**A040** (spec #40) - Correct the HSN/SAC linkage: Linked Tax must be a LIVE dropdown of real, editable tax heads, never a fixed label typed into the row. **A041** (spec #41) - Keep the Saturday pattern as its own policy field and NOT as holidays. A working Saturday is not a holiday and an off Saturday is not one either - holidays are dated events in the Holidays calendar, while Saturdays are a recurring pattern that must be resolved for all fifty-two of them before anyone can count a month's working days. Keeping them separate also settles the collision: a MANDATORY holiday always overrides the Saturday rule (15-08-2026 is a 3rd Saturday the odd pattern would make working; Independence Day makes it non-working and required hours drop to zero); an OPTIONAL holiday does NOT override it.

**A042** (spec #42) - Make every Work Week number a configured field rather than a written-down constant, and support MORE THAN ONE policy, each scoped to who it covers, with the narrower policy always winning over the company-wide default for the people it names. The eight-hour day, one-hour break, forty-hour week and odd/even Saturday pattern are this company's current answers, not universal truths - a support team on a rotating six-day week, an intern on half days and a contractor on a flat six-day week all need different targets against the same attendance data. Hard-coding '8' or 'odd Saturdays' would mean a code change every time an answer moved and would quietly misprice everyone who does not fit the default.

**A043** (spec #43) - Keep Salary Credit Day and End Day as two deliberately separate fields. End Day decides which events a run INCLUDES; Salary Credit Day decides when money actually LANDS, which is always later, because there must be time between the two for Accountant or Super Admin to run, review and confirm payroll. Conflating them would either force the cutoff dangerously close to payday, or delay payday to match a cutoff with no reason to move.

**A044** (spec #44) - Do not build a volume or spend report on Recent Sends. It is a small read-only troubleshooting log for one specific delivery - the same distinction already established for Vendor Usage (Module 7, Section 2.3) applies here.

**A045** (spec #45) - Build the Daily Hours hour-band table as read-only and always visible. It is what makes the rule AUDITABLE - the difference between 'the system decided' and 'here is the band it fell into'.

**A046** (spec #46) - Build the Taxes live worked-example panel as a deliberately prominent element, not an afterthought. The person entering a tax is being asked to describe a calculation in the abstract, and the fastest way to catch a wrong ceiling, an inverted slab or a mis-set split is to see one number come out wrong BEFORE it reaches a payslip.

**A047** (spec #47) - Implement the module-specific Used / Unused filter on every sub-master list. It is what makes 'which of these can I safely deactivate?' answerable without opening each entry one at a time.

**A048** (spec #48) - Implement Created By, Last Modified By and Created On range filters on every sub-master list. Masters is confidential shared configuration, and knowing who changed a shared list and when is worth more here than almost anywhere else in the CMS.

**A049** (spec #49) - Build Masters as ONE settings page with a left-side vertical tab list, not 19+ separate pages. Reasons: it keeps every configuration screen inside one predictable contained area rather than scattered across the main menu; it matches how most business software organises a Settings area so it feels familiar; and it makes access control simple to reason about, decided in one place per role rather than scattered across many screens. Selecting a tab must swap only the main content area - the page never reloads or navigates away.

**A050** (spec #50) - Place Masters as its own item near the BOTTOM of the main left-hand sidebar with a gear icon, deliberately set apart from the day-to-day operational modules listed above it, to signal that it is configuration rather than daily work.

**A051** (spec #51) _[resolved-historical]_ - Confirm no further Masters additions are open. Service Category, Unit of Measure, Ticket Categories, Customer Status, Customer Source, Asset Categories, Employment Type and Email Configuration are all BUILT, resolving the open gaps flagged in the Ticket (Module 4), Customer (Module 8), Asset Management (Module 3) and Employee (Module 2) documents.
